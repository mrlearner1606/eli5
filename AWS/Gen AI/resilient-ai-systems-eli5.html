Resilient AI Systems

ELI5: Your AI app is a cricket team. When the star batsman gets hurt, you bring in a backup, and if the whole ground floods, you move the match to another ground. Resilience means the match never stops.

1. The big idea

Things will fail: a model gets throttled, a Region has a bad day, a dependency goes quiet. Resilience means you planned the backup before the failure, so the user still gets an answer, even if it is a slightly different one.

Cricket version: the star batsman is injured. A good captain already knows who comes in next. A bad captain panics.

2. Fallback model patterns

Try the primary model. If it fails, try a backup model. If that fails too, return a friendly message.

Primary model ✗
→
Backup model ✗
→
Friendly message ✓

Bedrock Intelligent Prompt Routing is a native option that picks a model by quality and cost. It does not replace your own failover logic.

3. Cross-Region inference (CRIS)

Bedrock spreads your requests across several Regions in a geography, so one Region's quota or throttling does not stop you.

Your request
→
Region A
Region B
Region C

Important: CRIS is a capacity mechanism. AWS's own resilience post says it is not a failover or disaster-recovery mechanism. For a full regional outage you need a multi-Region application tier.

4. Circuit breaker

Like a house fuse. If a dependency keeps failing, the breaker trips and calls stop going to it, so the system fails fast and uses the fallback instead of piling on load.

CLOSED: calls go through→ too many failures → OPEN: fail fast, use fallback→ after timeout → HALF-OPEN: one probe call
  • Probe succeeds → back to CLOSED.
  • Probe fails → back to OPEN.
  • Where the state lives matters. Store it in DynamoDB or AppConfig, keyed per model and Region. A counter in one Lambda's memory is not shared, so each instance would decide on its own.

5. Route 53 health checks

Route 53 is the traffic police at DNS level. It checks each Region's endpoint, and when one is unhealthy it sends users to a healthy Region.

Route 53 health check
→
Region A unhealthy
→
Region B serves traffic

  • Each Task gets its own timeout, so a hung call cannot block the flow.
  • Retry and Catch send failures to the fallback path.

7. Retry vs circuit breaker

Retry with backoff + jitter

Good for occasional throttling. Wait a little, try again, add randomness so retries do not stampede together.

Circuit breaker

Good for a sick dependency, for example 9 of 10 calls failing. Stop calling it for a while so you do not add load to a system that is already down.

8. Exam traps

If the answer says…Why it is a trap
Retry with backoff only, for a hard outageWrong. Use a circuit breaker to stop calling a dead dependency.
Keep breaker counters in memory per LambdaWrong. State is not shared. Use DynamoDB or AppConfig.
Cross-Region inference alone is disaster recoveryWrong. CRIS is capacity. Add multi-Region plus Route 53 for failover.
