Why bother?

the model guesses too fast

Big models are 🎲 guess machines

They write the next word. One jump from question to answer = one chance to slip. Give it room to write the steps and each step keeps the next one honest.

Chain of Thought

= “show your work”

The whole trick is one sentence

Add “Let's think step by step.” to your prompt.

No new model. No training. Same model, extra sentence. You can also show a worked example (few-shot) if the steps are weird.

Real chain examples come from your code or your Knowledge Base — not from the model's imagination.

    ReAct

    Reason + Act = think, use a tool, look, repeat
    Think 🤔 — “What do I actually need to know?”

    Tap a bubble on the wheel. Each turn = one Thought, one Action, one Observation.

    🧾 A ReAct trace, as a comic strip

    🤔Thought“Is my flight delayed?”
    →
    🔧Actioncall flight-status API
    →
    👀Observation“delayed 40 min”
    →
    🤔Thought“then I must rebook”
    →
    ✅Finaltell user + rebook
    🧠 Model just asks ⇢ ⚙️ Your code runs the tool ⇢ 📥 result goes back into the chat ⚠️ The model never runs anything itself. You own every tool, and you can say “no”.

    The classic interview question

    “When is ReAct better than CoT?”

    When the answer lives outside the model. CoT thinks with what it already knows; ReAct goes and gets the missing fact — then keeps thinking.

    Traps (the fine print)

    ⏱️ More steps = more money

    Every thought and tool call is billed tokens. Latency climbs too.

    🌀 Runaway loops

    Cap steps and timeouts, or an agent will happily think forever.

    🙅 It never runs code

    The model only asks. Your Lambda, API or KB does the doing.

    😎 Fluent ≠ correct

    A neat chain can still be wrong. Read the trace, check the facts.

    🫥 Don't leak the chain

    Steps can expose prompts, PII or internal tool names. Summarise, don't dump.

    🧨 Tools are the risk

    Least-privilege IAM, schema validation, Guardrails on tool input & output.
